# Catatan Keputusan Desain

Daftar keputusan penting proyek beserta alasannya, sebagai bahan menjawab "kenapa memilih ini?" saat presentasi.
Tambahkan baris baru setiap ada keputusan yang mengubah kontrak, arsitektur, atau hyperparameter final, lalu kabari grup.

| ID | Keputusan | Alasan | Sumber |
|---|---|---|---|
| D-001 | Model Pix2Pix (Conditional GAN) | Termasuk pilihan di panduan proyek; dataset berpasangan tersedia dan hasilnya mudah dievaluasi secara visual | [log 00](logs/adrian/00-perencanaan-arsitektur.md) |
| D-002 | Dataset edges2shoes, subset ±10.000 pasangan, 256×256 | Sudah berpasangan (sketsa–foto) dan cukup ringan untuk GPU gratis. Batasan: model hanya bisa menghasilkan sepatu | [log 00](logs/adrian/00-perencanaan-arsitektur.md) |
| D-003 | GitHub untuk kode, Kaggle Notebook (GPU T4/P100) untuk training | Gratis, GPU cukup untuk 256×256, dan repo bisa langsung di-clone di notebook | [log 00](logs/adrian/00-perencanaan-arsitektur.md) |
| D-004 | Generator U-Net 8 lapis dengan skip connection | Skip connection membawa detail garis sketsa langsung ke decoder sehingga struktur gambar tetap terjaga | [log 00](logs/adrian/00-perencanaan-arsitektur.md) |
| D-005 | Discriminator PatchGAN 70×70 | Menilai keaslian per patch lokal (tekstur) dengan parameter lebih sedikit daripada menilai satu gambar utuh | [log 00](logs/adrian/00-perencanaan-arsitektur.md) |
| D-006 | Loss BCEWithLogits (adversarial) + 100 × L1 | L1 menjaga hasil tetap mirip foto asli, adversarial membuat hasil tajam; bobot 100 mengikuti paper Pix2Pix | [log 00](logs/adrian/00-perencanaan-arsitektur.md) |
| D-007 | Adam, lr 2e-4, betas (0.5, 0.999) | Pengaturan umum untuk GAN; β1 0.5 membuat training lebih stabil | [log 00](logs/adrian/00-perencanaan-arsitektur.md) |
| D-008 | Kontrak data `(sketch, photo)`, `[B, 3, 256, 256]`, float32, rentang `[-1, 1]` | Supaya ketiga modul bisa dikerjakan paralel; rentang `[-1, 1]` cocok dengan output Tanh di Generator | [log 00](logs/adrian/00-perencanaan-arsitektur.md) |
| D-009 | Kelompok 3 orang: Rian merangkap peran Anggota 1 dan 4 | Panduan mengasumsikan 4 anggota, sedangkan kelompok kami 3 orang | [log 00](logs/adrian/00-perencanaan-arsitektur.md) |
| D-010 | Log interaksi: 1 file = 1 sesi chat, setiap komponen dan bug menjadi entri tersendiri | Template dosen memakai kolom Tanggal Sesi dan Tautan Sesi Chat, jadi satuan log adalah sesi chat | [logs/TEMPLATE.md](logs/TEMPLATE.md) |
| D-011 | Inisialisasi bobot N(0, 0.02) untuk Generator dan Discriminator, BatchNorm gamma N(1, 0.02) | Konvensi DCGAN/Pix2Pix; pada input acak, piksel saturasi Tanh turun dari 1,26% ke 0,00% | [log 03](logs/adrian/03-discriminator-init.md) |
| D-012 | Loss D = 0,5 × (loss real + loss fake) | Mengikuti paper Pix2Pix; D belajar lebih lambat dari G supaya G tidak kalah terus | [log meyra 01](logs/meyra/01-training-loop.md) |
| D-013 | Checkpoint `latest.pt` ditimpa tiap epoch dan ditulis atomik (`.tmp` lalu `os.replace`); `epoch_XXX.pt` hanya jika `--keep_all` | Satu checkpoint (G, D, dua state Adam) ratusan MB, menyimpan semua epoch bisa memenuhi disk Kaggle; penulisan atomik mencegah file rusak jika sesi mati | [log meyra 01](logs/meyra/01-training-loop.md) |
| D-014 | `num_epochs` adalah target total; `--resume` melanjutkan dari epoch tersimpan (bobot, state optimizer, dan history ikut dipulihkan) | Training bisa dilanjutkan setelah sesi Kaggle putus atau diperpanjang tanpa mengulang dari nol | [log meyra 01](logs/meyra/01-training-loop.md) |
| D-015 | Validasi tiap epoch berupa rata-rata L1 di seluruh val (200 gambar) dengan `G.eval()` + `no_grad()`; sampel gambar tiap epoch dari satu batch val yang tetap | L1 val memantau generalisasi; batch tetap membuat perkembangan visual antar epoch bisa dibandingkan untuk laporan dan presentasi | [log meyra 01](logs/meyra/01-training-loop.md) |
| D-016 | Batch size 16 (default `main()`), bukan 1 seperti paper; 1 epoch (10.000 gambar) ±8,5 menit di GPU Kaggle | Lebih cepat dan stabil dengan BatchNorm; waktu 1 epoch diukur di run uji 1 epoch (loss D 0,4412; loss G 26,1877; val L1 0,5720) | [log 02](logs/meyra/02-integrasi-kaggle.md) |
| D-017 | Validasi dan sampel gambar menjalankan Generator dalam mode `train()` di bawah `no_grad()` (BatchNorm memakai statistik batch, Dropout aktif), bukan `eval()`; mode semula dipulihkan setelahnya, `model.py` tidak diubah | Mengikuti pengujian di paper Pix2Pix. Opsi ganti ke InstanceNorm ditolak karena mengubah arsitektur dan perlu training ulang. Konsekuensi: sampel dan val L1 sedikit acak, dan running stats BN ikut terisi data val | [log 02](logs/meyra/02-integrasi-kaggle.md), [log 03](logs/meyra/03-perbaikan-mode-eval.md) |
| D-018 | Eksperimen tuning batch size 8 vs 16 (12 epoch, lr 2e-4, seed 42): batch 16 dipertahankan | val_L1 rata-rata epoch 4-12: 0,1727 (batch 16) vs 0,1770 (batch 8); epoch 12: 0,1619 vs 0,1771. Tidak ditemukan bukti batch 8 lebih baik. Kesimpulan tidak diklaim sebagai "batch 16 lebih baik" karena tercampur dengan jumlah update (7.500 vs 15.000) dan ukuran batch validasi (16 vs 8); satu seed per konfigurasi, lr tidak divariasikan. Pembanding PSNR/SSIM pada batch validasi yang sama menyusul | [log 04](logs/meyra/04-tuning-batchsize.md) |
| D-019 | Inferensi memakai batch sketsa pendamping: sketsa pengguna dijalankan bersama 7 sketsa dari `assets/context_sketches/` dalam satu batch mode `train()`, hanya keluaran indeks 0 yang diambil (`--no_context` untuk batch 1) | BatchNorm mode `train()` memakai statistik batch. | D-020 | Evaluasi kuantitatif: PSNR dan SSIM pada 200 gambar val, Generator mode `train()` (D-017), batch 16, seed 42, `data_range=1,0`, SSIM parameter bawaan scikit-image (`channel_axis=-1`), dihitung per gambar | Metrik standar image-to-image translation.
